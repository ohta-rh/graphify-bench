三つ目のインデックスでも、素の Claude Code は抜けない。code-graph-rag は MemPalace より安く、graphify よりターンを食う。

AST グラフを Memgraph に入れて MCP で引く code-graph-rag 0.0.845 を、graphify・MemPalace と同じ 65 問・同じ採点で測った。130 run、$28.55。自前の LLM で Cypher を書く看板機能は外し、LLM を使わない 9 つのグラフツールだけを渡している。

前回までの結論（graphify 対 素の Claude Code）に、インデックス形状を一つ足して同じ問いを繰り返した記録。

中で何が起きていたか

費用が素と変わらないのに使用量が 39% 増えた理由はターン数にある。中央値で素が 5 ターン、graphify が 9、code-graph-rag は 14。ツールが返すものが小さいからだ。9 つのツールが 45 run で返した合計は 353 KB で、MemPalace の 4.0 MB の 11 分の 1。その代わり semantic_search でシンボル名を得て get_code_snippet で本体を取る、という細かい往復を run あたり中央値 6 回繰り返す。ターンが増えるたびに固定コンテキストが再送され、それが使用量の差になる。

使われたツールは 4 つだけだった。semantic_search 176 回、get_code_snippet 154 回、ast-grep による structural_search 40 回、Haiku だけが get_function_source を 20 回。重複検出・データフロー・トレースバック系の 5 ツールは 130 run で一度も呼ばれていない。

Haiku 4.5 では崩れる

graphify は弱い探索者ほど助かる（Haiku で −21%）という結果だったが、code-graph-rag は逆に出た。正答は 32/44 で素の 36/45 を下回り、graphify（Haiku）に対しては使用量 +74%、費用 +31% と本物の負け。45 run のうち 9 run はツールを一度も呼ばず、1 run は 60 ターンを使い切って答えを出せなかった。9 つのツールと taskflow-v1.src.lib.permissions.can という形の名前を、Haiku は使いこなせていない。

文書↔コードでは検索が届かない

文書 139 本は見出しごとに 1,442 個の Section ノードとしてグラフに入っている。しかし semantic_search が埋め込むのは関数だけで、Section は検索に掛からない。エージェントは文書を自分で grep するしかなく、索引の恩恵は関数側だけになる。

それでも正答は素の 14/20 に対して 15/20、MemPalace の 12/20 を上回り、仕込まれた矛盾の検出は 3/4（素 2/4、MemPalace 2/4、graphify 4/4）。ただし 20 問では費用・使用量のどの比較も幅がゼロをまたぐ。

どう測ったか

  • コーパス・65 問・採点・実行設定（claude -p、effort high、--max-turns 60）はこれまでと同じ。CLAUDE.md は素の文面に ## code-graph-rag の一節を足しただけで、graphify・MemPalace の一節と同じ長さ・同じ形。
  • グラフは Tree-sitter で 496 ファイル（文書込みで 635）を解析し、共有の Memgraph に入れた。埋め込み（UniXcoder）は Qdrant サーバへ。run ごとの複製はなく、130 run が同じ読み取り専用グラフを引く。
  • MCP サーバは --strict-mcp-config で唯一のサーバとして繋ぎ、--disallowedTools で 12 ツールを外した: 自前 LLM を呼ぶ ask_agent・query_code_graph、グラフやファイルを書き換える 8 ツール、staging 側のファイルを読む read_file・list_directory。残る 9 ツールは LLM を使わない読み取り専用。
  • 指標は uncached_equivalent_all（全モデル分の入力 + キャッシュ書き込み + 読み出し）と total_cost_usd。差はタスク対の平均差で、95% の幅は 2,000 回のブートストラップ。

気をつけること

  • code-graph-rag の看板は自然言語を Cypher に翻訳して答える機能で、それは測っていない。この結果は「データベースに置いた AST グラフはエージェントに何をもたらすか」であって、製品の評価ではない。
  • 反復は 1 回。正答の差は 1〜2 問で、45 問では雑音と分けられない。
  • 導入で二つ躓いた: mcp ライブラリを 2 未満に固定しないと MCP サーバが起動直後に落ちる。QDRANT_URL を全工程に渡さないと埋め込みが作業ディレクトリ相対のローカル DB に書かれ、検索が空を返す。どちらも docs/plan/CGR.md に記録した。
  • 実時間は並列 3 で測った二次的な数字。1 呼び出しの遅延のほうが頑健。
